[role="lead"]
Workload Security는 스토리지에서 사용자 활동을 모니터링하고 잠재적인 보안 위협을 감지합니다. 사용자 환경에 설치하는 에이전트는 스토리지 시스템에서 파일 및 사용자 액세스 데이터를 수집하고 디렉터리 서버에서 사용자 정보를 수집하는 컬렉터를 호스팅합니다.

아래 작업을 순서대로 완료하십시오. 각 작업은 이전 작업에 종속되므로, 에이전트가 연결될 때까지 수집기를 추가할 수 없으며, 디렉터리 수집기가 존재하기 전까지는 활동이 사용자 이름으로 변환되지 않습니다.

[[step-1-size-and-prepare-the-agent-host]]
== 1단계 - 에이전트 호스트 크기 조정 및 준비

다른 응용 프로그램 수준 소프트웨어가 실행되지 않는 전용 Linux 호스트에 에이전트를 설치하십시오.

* 호스트가 운영 체제, CPU, 메모리 및 디스크 요구 사항을 충족하는지 확인하고 고정 IP 주소를 할당하십시오. 현재 지원되는 Linux 버전 목록은 에이전트 추가 페이지의 지원되는 Linux 버전을 참조하십시오.
* NTP를 사용하여 에이전트 호스트와 ONTAP의 시간을 동기화합니다.
* 에이전트가 호스팅할 컬렉터 수를 결정하기 전에 Event Rate Checker를 사용하여 최대 이벤트 발생률에 맞게 크기를 산정하십시오. 에이전트는 모든 유형의 컬렉터를 합쳐 최대 50개까지 지원하며, 초당 최대 이벤트 수는 20,000개입니다.
* 네트워크 경로를 계획하십시오. 에이전트는 TCP 443을 통해 ONTAP 관리에 연결하고 TCP 443을 통해 Workload Security 서비스에 연결하며, ONTAP은 TCP 35000-55000 내에 예약된 포트를 통해 에이전트에 다시 연결합니다.




[[step-2-deploy-the-agent]]
== 2단계 - 에이전트 배포

* 관리자 또는 계정 소유자로 로그인하여 *수집기 > 에이전트 > +에이전트*를 선택하십시오.
* 네트워크에서 프록시 서버를 사용하는 경우 설치 프로그램 스니펫을 실행하기 전에 프록시 세부 정보를 설정하십시오.
* *설치 프로그램 스니펫 복사*를 클릭합니다. 스니펫에는 2시간 동안 유효하며 에이전트 하나에만 사용할 수 있는 고유 키가 포함되어 있습니다.
* 에이전트 호스트에서 해당 코드 조각을 실행한 다음 브라우저로 돌아가서 *설정 완료*를 클릭합니다.
* *수집기 > 에이전트*에서 에이전트가 *연결됨*으로 표시되는지 확인하십시오.



NOTE: 에이전트 호스트의 방화벽을 포함하여 에이전트 방향으로 예약된 FPolicy 콜백 포트를 여십시오. 이 경로가 열릴 때까지 ONTAP은 이벤트를 전달할 수 없습니다.



[[step-3-configure-a-user-directory-collector]]
== 3단계 - 사용자 디렉터리 수집기 구성

이 컬렉터를 첫 번째 ONTAP SVM 컬렉터와 함께 또는 그 전에 구성하십시오. 이 컬렉터가 없으면 Activity Forensics에서 사용자 이름 대신 인코딩된 식별자(SID)가 표시됩니다.

* 신뢰할 수 있는 도메인을 포함하여 모니터링 대상 SVM에 액세스하는 사용자가 있는 모든 도메인에 대해 수집기를 하나씩 추가합니다.
* Active Directory의 경우 표시 이름을  `name`에, ID를  `objectsid`에, 사용자 이름을  `sAMAccountName`에 매핑합니다.
* LDAP 디렉터리 서버의 경우 표시 이름을  `name`에, ID를  `uidnumber`에, 사용자 이름을  `uid`에 매핑합니다.
* 디렉터리 서버에서 SSL을 활성화해도 수집기가 차단되지 않습니다. Workload Security는 서버가 제공하는 인증서를 허용합니다.



NOTE: 사용자 디렉터리 수집기에서는 연결 테스트를 사용할 수 없습니다. 평소 사용하는 디렉터리 툴을 사용하여 서버, 포트, 바인드 계정 및 검색 베이스를 검증한 다음, 수집기가 *실행 중* 상태가 되는지 확인하십시오.



[[step-4-configure-the-ontap-svm-data-collector]]
== 4단계 - ONTAP SVM 데이터 수집기 구성

* 연결 방법을 선택하십시오. SVM 모드에서는 기능 및 RBAC 검사를 실행할 수 없으므로 SVM 이름과 함께 클러스터 관리 IP를 사용하는 것이 좋습니다.
* 먼저 ONTAP 계정을 준비하십시오.  `cluster-admin` 자격 증명을 사용하거나 필요한 권한이 있는  `csuser` 및  `csrole`을(를) 생성하십시오. 연결 테스트는 이 계정으로 실행되므로 권한이 확보될 때까지 FPolicy 또는 선택적 기능을 검증할 수 없습니다.
* *컬렉터 > +데이터 컬렉터*를 선택하고 NetApp SVM 타일 위로 마우스를 가져간 다음 *+모니터*를 클릭합니다.
* 수집기 정보를 입력하고 저장하기 전에 *연결 테스트*를 클릭하십시오.
* 실패한 검사를 모두 해결한 다음 컬렉터를 저장합니다.



NOTE: 연결 테스트는 네트워크 검사를 바탕으로 SUCCESS를 보고합니다. 기능 결과는 참고용이므로 스냅샷, 액세스 거부, 자율 랜섬웨어 보호, 영구 저장소 또는 사용자 차단 등 사용하려는 각 선택적 기능에 대해 검토하십시오.



[[step-5-verify-that-data-is-flowing]]
== 5단계 - 데이터 흐름이 정상인지 확인합니다

* 수집기가 *실행 중* 상태가 되었는지 확인하십시오.
* 모니터링 대상 SVM에서 실제 SMB 또는 NFS 클라이언트 활동을 생성합니다. 클라이언트 I/O가 없으면 이벤트가 발생하지 않습니다.
* *Workload Security > Activity Forensics*에서 해당 활동이 나타나는지 확인하십시오.
* 활동 내역에 SID가 아닌 사용자 이름이 표시되는지 확인하십시오. 그렇지 않은 경우 User Directory Collector를 확인하십시오.
* 수집기가 *오류* 또는 *성능 저하*를 보고하는 경우 *상태 > 자세히 보기*를 열고 ONTAP SVM 데이터 수집기 문제 해결을 따르십시오.




[[optional-next-steps]]
== 다음 단계 (선택 사항)

* 다른 사람들에게 Workload Security에 대한 액세스 권한을 부여하려면 사용자 계정을 생성하십시오. 이는 데이터 수집에는 필요하지 않습니다. Workload Security 사용자 관리를 참조하십시오.
* 선택적 수집기 기능을 활성화하십시오. 각 기능에는 고유한 ONTAP 버전 및 권한 요구 사항이 있습니다.
* Workload Security를 Splunk 등 다른 툴과 통합하십시오.
